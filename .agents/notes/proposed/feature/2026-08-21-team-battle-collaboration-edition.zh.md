# Agent Note: 团战版多人协作产品

Status: proposed

[English](2026-08-21-team-battle-collaboration-edition.md) | 中文

## 问题

DeepSeek Harness 当前以一个人使用一个 agent（智能体）运行为中心：人说明目标、约束和判断，agent 负责实现。进入多人项目后，这个高效的个人闭环仍要回到会议、语音、聊天软件和人工交接。产品、研发、测试和 UI 成员各自拥有与 Codex 或其他 agent 的对话与产物，但后续角色无法直接继承前序工作的完整项目上下文，只能再次由人转述、筛选和解释。

把完整的私人对话复制到共享聊天会暴露无关或敏感信息，也仍然不能形成责任明确的任务、验收和项目进度。传统项目看板可以记录状态，但无法把这些状态双向连接到每个成员自己的 agent，也不能让跨角色进展形成直观、有情绪反馈的体验。

团战版需要把“一个人与一个 agent 协作”扩展成“一群人与各自拥有的 agent 围绕同一项目协作”。每个人继续在自己的 agent 中工作，经过本人确认的对话纪要、人的判断和原始产物汇入统一项目空间。团队成员与各自 agent 可以看到可追溯的项目全貌，从前序成果继续工作，再把新的判断和产物写回同一个项目 Context。游戏把共同攻克项目表现为合作打 Boss，并在等待 agent 回复时提供真正可玩的消遣，但不取代项目空间。

## 提案

把团战版建设成通过专用 `lowpower.me` 子域名公网可访问的跨 agent 项目空间。首次部署服务一个仅限邀请的团队工作区，不提供匿名访问、公开项目发现或自助多租户注册。它不是一个共享 agent 群聊、传统项目看板或给当前单进程 Agent Teams 实验套一层远程界面；它的核心产品是能够被人和 agent 共同消费、持续接力并保留来源的项目 Context。

产品分成三层：

| 层级 | 权威范围 | 职责 |
|---|---|---|
| 项目事实层 | 共享项目状态的真源（source of truth） | 管理项目、胜利条件、任务、依赖、上下文包、产物、验收、决策、权限和审计事件。 |
| Agent 中继层 | 消息投递记录的真源 | 与每位成员的个人 agent 交换经过批准的结构化进展、任务、上下文、产物和回执，但不把私人对话历史据为己有。 |
| 游戏投影层 | 仅为派生状态 | 把已验收的项目事件转换成权威 Boss 血量和阶段，并把每个去重 Query 转换成一次仅影响休闲战局的特殊武器发放；它本身永远不能修改项目事实。 |

团战板管理共享工作、项目 Context 和验收状态。用户发布用于协作的产物时，项目空间保存内容不变、可校验、带权限的版本副本以及来源信息，使后续成员和 agent 不依赖原作者在线也能继续；Git、PR、CI、设计或文档系统仍可作为产物的来源与完整历史所有者。人类用户始终对自己的 agent 发布或执行的行为负责。

## 产品原则

- **默认共享可接力的项目 Context，而不是原始私人对话。** 个人 transcript（文本记录）留在本地，除非用户明确选择片段共享。常规发出单位是经过检查的协作纪要、Context Packet（上下文包）、任务进展、决策、阻塞、改动日志或原始产物。
- **整理对话不能美化事实。** 连接器把选定对话整理成协作纪要，区分已经确认的事实、人的判断、agent 建议、分歧、失败尝试和未解决问题。整理可以提高可读性，但不能抹平冲突、改变结论或把推测写成决定。
- **人的判断与原始产物分别保真。** 人的接受、否决、取舍和不可改写约束单独记录；文档、设计、代码、测试报告和日志保持原样并带有来源、版本和校验信息，不经过摘要替代。
- **项目全貌可导航，不等于把全部历史塞进提示词。** 团队成员和 agent 可以浏览完整的来源图、版本与上下游关系；投递到个人 agent 的内容按当前任务组装，并链接到可继续检索的完整项目空间，避免超长、过期或越权上下文。
- **双向不等于静默远程控制。** 团战板可以把任务和上下文投递给个人 agent，但唤醒或指挥该 agent 需要单独、可见的权限和回执。
- **由证据推动项目。** 对话数量、token 用量、代码行数和在线时长永远不能决定进度。已经验收且带权重的交付物和胜利条件才能决定进度。
- **Query 奖励游戏，但不能冒充进度。** 每个发送成功且去重后的用户 Query（查询）只发放一次特殊武器，例如清屏核弹或限时强化子弹。普通移动、自动射击、击杀、得分和开始任务都不发放这类武器，特殊武器也永远不修改项目完成度或项目 Boss 血量。
- **每个权威效果都能追溯到事实。** Boss 血量、阶段和已验收成果技能都能打开导致它的任务、产物、验收和操作者。特殊武器发放只追溯到不含 Query 文本的稳定事件 id、来源成员和连接器。
- **游戏表现必须保留严肃工作视图。** 相同数据在减少动态效果或非游戏看板视图中仍然完整可用。
- **角色属于项目配置。** 产品、研发、测试和 UI 是第一套模板，而不是写死的数量限制或权限模型。

## 共享项目 Context

个人协作循环以一次可以接力的 `CollaborationUpdate`（协作纪要）汇入项目空间。它不是聊天截图或装饰后的聊天气泡，而是一个有来源、有版本、有受众且经过本人确认的项目贡献，包含三类并列内容：

1. **结构化对话纪要。** 记录目标、约束、已确认事实、方案变化、失败尝试、未解决问题和建议下一步，并为每项关键结论保留来源锚点。
2. **人的判断。** 明确本人接受、否决、修改或保留了什么，为什么这样决定，以及哪些约束不能由后续 agent 自行改写。
3. **原始产物与证据。** 保存外部文件、设计、代码提交、测试报告、文档或日志的原始引用、版本、作者、时间和校验状态；摘要只能帮助发现，不能替代产物本身。

连接器先在个人设备上根据用户选定的会话范围生成 `ShareDraft`（共享草稿），执行敏感信息提示和来源锚定。用户可以编辑、删减、脱敏、选择接收人、敏感级别与有效期，再发布到项目空间。界面必须区分“AI 整理草稿”“本人已确认”和“本人编辑后发布”；项目负责人或管理员不能绕过本人读取完整私人对话。

项目空间把协作纪要、任务、决定、产物、验收和更正组织成有来源的版本图，并派生一个当前 `ProjectContextSnapshot`（项目上下文快照）。快照回答项目目标、当前状态、已经确认的判断、可复用成果、正在推进、待解决问题、阻塞、下一位接手者和最近变化。后续角色可以检查来源，接过一项工作，把任务范围内的 Context 投递到自己的 agent，再把新结果作为派生版本写回。

发布后的协作纪要不能静默改写。更正会创建新版本，旧版本标记为已被更正，并通知已经接收或继续使用旧版本的成员。缺失来源、陈旧内容、版本冲突、越权引用和无法访问的产物必须显示为断点，不能伪装成已经同步的当前事实。

## 用户与角色

- **项目负责人。** 创建项目 Boss，定义胜利条件和里程碑权重，配置项目角色，并指定最终验收人。
- **贡献者。** 认领或接收工作，使用个人 agent，发布协作事实与产物，并响应验收或依赖请求。
- **验收人。** 检查证据，接受或驳回交付物，并以此批准正式进度。
- **观察者。** 只读查看进展、风险、决策和结果，不改变项目状态。
- **工作区管理员。** 邀请成员，管理 agent 连接、权限、保留、导出和撤销。
- **协调 agent。** 整理进展、路由依赖并提醒阻塞；默认不能验收工作、合并代码、部署、发布或宣布胜利。

业务角色与权限角色分离。贡献者可以标记为产品或 UI，而权限授权决定此人是否能分配任务、发布受限上下文、验收工作或管理连接器。

## 产品模型

首个模型包含以下持久实体：

- `Workspace`（工作区）：成员、策略、连接器以及一个或多个项目。
- `Member`（成员）：人类身份、展示资料、权限授权和项目角色。
- `AgentConnection`（agent 连接）：一个成员拥有的一条 Codex 或其他 agent 工具连接，包含能力、状态、同意策略和撤销状态。
- `RaidProject`（团战项目）：共享目标、生命周期、参与者、项目角色和完成状态，由一个 Boss 表现。
- `VictoryCriterion`（胜利条件）：带有权重、证据要求和指定验收人的必需可验收条件。
- `QuestTask`（任务）：带有状态、负责人、角色、依赖、优先级、权重、验收标准和修订号的任务。
- `CollaborationUpdate`（协作纪要）：由本人发布的版本化项目贡献，分别保存结构化对话纪要、人的判断、原始产物引用和下一步请求。
- `SourceAnchor`（来源锚点）：关联来源工具、会话、选定轮次或时间范围、作者、生成时间、可见权限与摘要版本，不要求中央服务保存完整原文。
- `ContextPacket`（上下文包）：带有来源引用、受众、敏感级别、版本、新鲜度、决策、阻塞和协作请求的整理摘要。
- `ProjectContextSnapshot`（项目上下文快照）：从当前有效的纪要、任务、决定、产物、验收和更正派生的可导航项目全貌，并支持按角色与任务组装投递内容。
- `Artifact`（产物）：文件、提交快照、测试报告、设计、文档或其他交付物的内容不变版本，包含来源引用、内容校验值、媒体类型、大小、访问权限、保留状态与派生预览；外部系统仍可保存权威历史。
- `ReviewDecision`（验收决定）：与证据和责任主体关联的接受、驳回、修改要求或重新打开操作。
- `RelayMessage`（中继消息）与 `DeliveryReceipt`（投递回执）：带有投递、确认、重试和过期状态的发出或接收协作内容。
- `AuditEvent`（审计事件）：对人类、agent、连接器和系统行为的仅追加记录，包含操作者、来源、时间、链路标识和幂等键。
- `GameProjection`（游戏投影）：由已验收项目事件派生的权威 Boss 状态，加上休闲战局、特殊武器库存和表现状态，永远不作为项目事实的真源。

每个持久事实都要区分人类操作、agent 代表人类执行的操作、协调 agent 操作、连接器投递和系统派生投影。展示名不能替代经过认证的身份。

`QueryPulse`（Query 脉冲）是一种短期连接器信号，只包含稳定 Query 事件 id、经过认证的成员与连接器、可选项目或任务 id 和发生时间，不包含 Query 文本。每个不同事件 id 恰好派生一个 `SpecialWeaponGrant`（特殊武器发放）；重试或重连复用同一 id，不能重复发放。该信号不是进度事实、保留的对话记录或绩效指标。

`ShareDraft` 是只存在于个人连接器中的临时对象。它在用户发布或丢弃前不属于团队项目记录，中央服务也不能把本地草稿显示成共享事实。

## 核心旅程

1. 项目负责人创建团战，命名 Boss，定义目标、胜利条件、里程碑权重、验收人和初始项目角色。
2. 负责人邀请成员。每位成员接受角色、连接自己的 agent，并选择连接器可以读取、发布、接收或执行什么。
3. 团队创建带有依赖、证据要求和权重的任务。成员认领工作或接收分配。
4. 成员登录后默认进入个人协作台，在同一个首屏与自己的 Codex 对话并直接游玩飞机大战。该对话默认为私人内容，不因与游戏同屏而自动进入团队空间。
5. 成员点击左侧「团队」 Tab（标签页）后，查看其他成员及其 agent 的工作状态，并进入团队云空间中的项目 Context、任务、产物和验收。选中前序成果后，团战板按任务组装 Context Packet，并在投递前预览任务、纪要、人的判断、原始产物、来源版本和不会发送的私人内容。
6. 成员与个人 agent 私下完成工作。每个发送成功的新 Query 发出不含内容的 Query 脉冲，为当前游戏发放一次特殊武器。等待 agent 回复时可以继续游玩；结果返回时界面提示已回复并保留战局，不强制暂停或离开游戏。
7. 连接器从用户选定的对话范围生成共享草稿，分别整理结构化对话纪要、人的判断和产物引用。用户对照来源编辑、脱敏、选择受众并发布，项目空间把它保存为不可静默覆盖的新版本。
8. 跨角色请求和新协作纪要会被路由到相关成员及其中继箱。投递回执显示每个目标是否已收到、已确认、已拒绝或错过该消息；后续 agent 可以从该版本继续并留下派生关系。
9. 贡献者提交原始产物引用和验收证据。提交可以产生蓄力动画，但不会降低 Boss 血量。
10. 验收人接受或驳回贡献。接受会推进带权重的胜利条件并触发一次幂等攻击；驳回会让任务回到返工且不制造虚假进度。
11. 只有所有必需条件都已验收并由项目负责人确认完成，Boss 血量才会归零。团战随后归档交付物、判断、协作纪要、上下文和审计事件。

## 中继内容与通道行为

首版协议接收这些协作载荷：任务创建或更新、任务分配或认领、协作纪要、人的判断、进展摘要、阻塞、协作请求、决策、上下文包、产物引用、验收请求、验收决定、更正与替代关系、改动日志、提及、投递回执和不含内容的 Query 脉冲。

每个中继信封包含稳定事件 id、工作区与项目 id、可选任务、协作纪要与产物 id、经过认证的操作者、来源 agent 或连接器、载荷类型与版本、简洁可读摘要、结构化字段、来源锚点、基于版本、派生版本、目标接收人、敏感级别、链路标识、幂等键、发生时间和可选有效期。Query 脉冲不含摘要和内容字段，带有很短的有效期。可以合并短时内的视觉提示，但每个已去重的不同事件 id 都必须独立发放一次武器。

团战板到 agent 的投递支持中继箱消息、需要确认的上下文注入，以及单独授权的唤醒并运行请求。连接器绝不能仅因普通共享文本来自团战板，就把它转换成工具调用或 shell 命令。远程内容是不可信输入，仍受个人 agent 的权限与审批规则限制。

团战板记录已排队、已投递、已确认、失败、拒绝和过期状态。重试复用同一个幂等键，因此重连不能重复创建任务、验收或 Boss 攻击。在目标工具允许的情况下，贡献者可以检查并撤销尚未投递的内容。

## 信息架构

1. **个人协作台**是默认首屏。左侧固定导航只需清楚露出「对话」和「团队」；主区同屏融合当前用户与个人 Codex 的私人对话和真正可玩的飞机大战。首屏只保留对话记录、输入框、agent 状态、战场、生命与得分、特殊武器槽和必要控制，不展开团队卡片、任务看板、Context 图或项目仪表盘。
2. **团队** Tab 展示其他成员与其个人 agent 的工作状态，并承载团队云空间。云空间内再组织项目大厅、项目 Context、任务、产物、验收、决定、阻塞、来源版本和审计。个人对话不在这里自动出现，只展示本人明确发布的协作纪要、判断与产物。
3. **我的中继箱**展示发给用户 agent 的任务与上下文、等待用户批准的共享草稿、投递失败、回执、旧版本警告和连接器状态。
4. **连接与权限**管理 agent 绑定、能力、可见范围规则、读取会话、生成草稿、发布纪要、接收任务、唤醒 agent、执行任务、撤销和审计记录等独立授权。
5. **团战档案**保存最终产物、已验收条件、关键判断、可复用上下文包、来源图、战斗复盘和项目导出。

首版个人协作台已选定[统一飞行甲板](../../../../apps/web/prototypes/team-battle-flight/concepts/chat-game-v3/unified-flight-deck.png)作为视觉框架。团队页已确认使用[团队空间方向](../../../../apps/web/prototypes/team-battle-flight/concepts/chat-game-v3/team-space-page.png)：成员与 agent 状态栏、任务工作区、共享 Context 与产物库、验收操作、活动、版本和来源。两个方向都不得把这些团队空间功能堆回首页。

## 游戏投影

- 飞机大战与个人 Codex 对话同屏并真正可玩。飞机自动射击；用户用鼠标横向移动飞机，或使用键盘 `←` / `→` 横向移动。游戏支持敌机、碰撞、生命、休闲得分、暂停和重新开始；个人 agent 返回结果时只提示已回复并保留战局。
- 一个项目对应一个 Boss；里程碑对应 Boss 阶段。
- 配置的项目角色对应参战阵容，同时始终展示真实业务角色名称。
- 每个发送成功且去重后的新 Query 恰好发放一次特殊武器；首版至少包含「清屏核弹」和「限时强化子弹」。鼠标点击武器槽或按 `Space`（空格键）使用当前特殊武器。
- 普通射击、特殊武器、清屏、强化、击杀、生命、波次、休闲得分和重新开始只改变当前游戏战局，不代表项目进度或个人绩效，也不能修改任务、项目 Context、完成度或项目核心。
- 提交产物会释放一次技能尝试或进入蓄力状态。
- 验收证据会让技能命中，并按已验收条件的权重减少 Boss 血量。
- 驳回证据会让技能落空，并把相关工作送回返工。
- 阻塞表现为带有负责人和关联解决任务的负面状态。
- 完成跨角色依赖链可以触发连击动画，但同一权重不能重复计算。
- 重新打开已验收工作会重新计算进度，并可能让 Boss 回血。
- 可复用交付物和已确认上下文包成为战后战利品，但不产生个人绩效分数。
- Boss 血量归零表示所有必需带权重条件均已验收；最后仍由人类确认关闭团战。
- 重新开始飞机大战只会重置当前波次、生命、强化和休闲得分，永远不能恢复项目核心、回滚任务或删除项目 Context。

投影把 `completionPercent`（完成百分比）与 `bossHealthPercent`（Boss 血量百分比）分开，Boss 血量由已验收完成度的补数派生。休闲战局另行维护波次、敌机、本局 Boss、生命、得分和 `specialWeaponInventory`（特殊武器库存）。只有已验收项目事实能改变权威项目 Boss；休闲战局的任何状态都不能被反向写入项目事实。

## MVP 范围

### 包含

- 通过专用 `lowpower.me` 子域名公网可访问的部署，首期服务于在不同电脑上工作的一个仅限邀请团队工作区。
- 可配置项目角色，并提供产品、研发、测试和 UI 的初始模板。
- 经过认证的人类账号、项目成员关系，以及只读、贡献、验收、负责人和管理员权限。
- 项目、胜利条件、带权重任务、依赖、认领、分配、阻塞、验收、驳回、重新打开、完成和归档。
- 优先支持 Codex 的连接器，以及供后续 agent 工具使用的带版本通用连接器协议。
- 带用户预览、确认、重试、过期和去重的双向结构化中继。
- 从选定个人对话生成的共享草稿、结构化对话纪要、人的判断、来源锚点、更正、替代关系和当前项目上下文快照。
- 上下文包、内容不变且可校验的产物版本、来源引用、访问权限、派生预览、证据、验收决定、改动日志和仅追加审计历史。
- 按任务和角色组装 Context，并在发送到个人 Codex 前预览内容、来源、版本与不会发送的私人信息。
- 无需手动刷新即可近实时更新的团战房间。
- 默认首屏同屏呈现个人 Codex 对话与飞机大战，左侧「团队」 Tab 可进入成员状态和团队云空间。
- 来自 Codex 的不含内容且去重的 Query 脉冲，每个不同事件 id 发放一次清屏核弹或限时强化子弹，不保存 Query 文本也不修改进度。
- Boss、血条、角色阵容、蓄力、攻击、连击、阻塞、阶段和胜利反馈，其权威伤害仍由已验收项目事实派生。
- 真正可玩的飞机大战，包括鼠标横向移动、键盘 `←` / `→` 横向移动、自动射击、敌机、碰撞、生命、休闲得分、特殊武器槽、暂停和重新开始。
- 承载相同任务、证据和进度的减少动态效果行为与非游戏看板视图。

### 不包含

- 自动上传或建立完整私人 agent 文本记录索引，或合并个人 agent 记忆。
- 静默远程执行命令、无限制唤醒 agent，或拥有万能权限的连接器。
- 在首个版本中支持所有 agent 产品。
- 取代 Git、PR、CI、设计工具或文档系统的完整历史与原始工作流；项目空间只保存用户明确发布的协作副本和来源。
- 根据消息、token、代码行、在线时长或个人伤害排行计算进度或绩效。
- 由 agent 自主完成验收、代码合并、部署、发布、付款或项目最终确认。
- 带有装备、货币、等级、竞技排行或付费推进机制的完整游戏经济。
- 公开项目发现、跨组织联邦或 agent 市场。

## MVP 成功信号

- 三至四名成员可以完成一次“任务 → 个人与 agent 协作 → 发布协作纪要和产物 → 下游角色接棒 → 人工验收”的闭环，无需另开会议或重新向下游口述已经记录的上下文。
- 离开项目一段时间的成员可以通过关键变化、来源和版本恢复项目全貌，并把选中的任务 Context 正确发送到自己的 Codex 继续工作。
- 每条已经发布的关键判断都有确认人和来源锚点，每个保存的产物版本都有内容校验值；未经本人确认上传完整私人对话的次数为零。
- 系统可以度量共享草稿到发布的时间、投递成功率、接收回执率、请求补充上下文率、纪要更正率和陈旧 Context 数量，用于改进协作质量，而不是评价个人绩效。
- 用户可以正确区分 Query 奖励、休闲战局和项目进度：只有新的去重 Query 发放特殊武器，游戏得分只属于消遣，只有已验收成果推进真实进度。

## 当前 Harness 基础

现有实验性 [Agent Teams](../../implemented/feature/2026-08-05-agent-teams.zh.md) 能力已经提供持久具名成员表、点对点邮箱、任务依赖图、乐观任务修订、投递确认和事件回放。这些语义可以作为团战版任务与中继行为的参考。

它的权限模型不能直接服务提案中的多人产品。Team 成员是同一个 Harness 进程内可以继续运行的直接子 agent，每个成员共享一个工作目录和代码检出目录，服务操作通过存活的进程内 agent 对象授权，而不是人类账号或远程连接器。该包没有远程成员、多人权限、跨进程邮箱、共享产物服务或 Web Team 控件。它自己的[包参考](../../../../packages/experimental/agent-team/README.zh.md)也记录了同进程限制。

[实验包决策](../../implemented/architecture/2026-08-18-experimental-agent-teams-packages.zh.md)还要求 Agent Teams 保持私有，不能进入官方发布包。团战版因此应新增一个中央认证项目服务与连接器协议，再把当前 Agent Teams 适配为一种本地连接器或参考实现。稳定 Web 包不应直接依赖实验包。

当前 Harness Web Host 是单用户本地服务。会话日志、投影、类型化远程调用、浏览器推送流、附件以及 SDK 或 ACP 进程适配器都可以作为实现材料，但经过认证的主体、多租户、项目 ACL（访问控制列表）、TLS 部署、按订阅者过滤事件、通用产物存储和经过认证的远程 agent 所有权仍然是新的产品工作。

| 决策 | 建议默认值 | 为什么会改变产品 |

| 角色 | 使用可配置角色和四角色初始模板；后续再讨论一人多角色 | 固定分栏无法适应不同结构的团队。 |

## 考虑过的替代方案

**由一个中央 agent 服务整个团队。** 未采用，因为它会把人类责任、私人工作上下文、工具权限和角色所有权压缩进一个对话。团战版改为协调分别由个人拥有的 agent。

**把每个人的私人对话完整镜像到共享聊天。** 未采用，因为原始对话含有无关和敏感内容，会造成过量上下文，并且仍然缺少明确任务、决策、验收和产物来源。

**只共享最终产物，不共享过程与判断。** 未采用，因为下游角色会看见结果却不知道目标、约束、取舍、失败尝试和未解决问题，仍然需要开会或向原作者追问才能继续。

**把所有纪要拼成一个不断增长的项目提示词。** 未采用，因为完整可见性不等于每次都注入全部历史。无限提示词会混入过期、冲突、越权和无关内容；团战版保留可导航的项目来源图，并按任务组装版本化 Context。

**使用没有游戏反馈的传统看板。** 未采用，因为合作战斗反馈属于用户要求的产品身份。事实看板仍然存在，而游戏状态是可追溯的投影，不是替代品。

**直接把当前 Agent Teams 服务改成多人服务器。** 未采用，因为它的权限依赖存活的子 agent 对象、单进程、单一 Lead Session 和共享代码检出目录。通过新连接器复用任务与邮箱语义，比削弱现有假设更安全。

**根据活动数量计算进度。** 未采用，因为消息数量和自报进度会奖励噪声且容易被操纵。每个去重 Query 可以发放一次休闲游戏武器，但只有带权重且通过验收的证据才能推进完成度并减少权威 Boss 血量。

## 验收标准

- 三名或四名受邀成员可以在不同电脑上访问公网服务，以不同配置角色加入一个项目，并连接分别属于自己的 agent。
- 成员可以认领或接收任务，批准投递，并观察到目标个人 agent 收到准确任务和选定上下文。
- 个人 agent 可以从用户选定的对话范围准备共享草稿，区分结构化对话纪要、人的判断和原始产物，由用户核对来源、编辑、脱敏并发布。
- 每条关键判断都保留确认人、来源锚点、基于版本和派生版本；更正不会覆盖历史，并能通知已经消费旧版本的成员。
- 用户明确发布的产物以内容不变版本保存，上传与授权下载后的校验值一致，派生预览不能替代原始内容。
- 离开项目一段时间的成员可以查看关键变化和当前项目上下文快照，从一项前序成果接棒，并把按任务裁剪的 Context 发送到自己的 agent，而无需读取全部私人对话。
- 已发布的跨角色请求可以到达目标成员，并显示已排队、已投递、已确认、失败或过期状态。
- 验收人可以依据指定标准接受或驳回产物，且决定始终关联操作者、证据、任务和来源。
- 一项已验收贡献即使经历重试、重连或重复投递，也只能修改一次带权重完成度和 Boss 血量。
- 默认首屏同屏展示当前用户的私人 Codex 对话和可玩飞机大战；左侧「团队」 Tab 可以进入其他成员与 agent 状态和团队云空间，且首页不展开这些内容。
- 每个不同 Codex Query 事件 id 恰好产生一次特殊武器发放；重复投递同一 id 不重复发放，也不发送 Query 文本或修改带权重完成度和 Boss 血量。
- 刷新或重连能够重建任务、回执、验收、审计历史与游戏状态，不依赖动画状态。
- 未授权成员与连接器无法在授权范围外读取、发布、验收、唤醒 agent 或管理资源。
- 每次权威伤害或血量变化都能打开导致它的已验收项目事实。特殊武器发放只标识来源成员和稳定 Query 事件 id，不会冒充进度；团队视图无需游戏操作也能保留完整工作流。
- 默认运行不会分享完整私人对话，也不会在没有配置的人类审批时执行远程 agent 命令。
- 用户可以用鼠标或键盘 `←` / `→` 控制飞机横向移动，普通子弹自动射击，并通过鼠标点击或 `Space` 使用 Query 发放的特殊武器。
- 暂停、重新开始、清屏、强化、击杀、得分以及本局 Boss 受伤只能改变休闲战局，不能改变任务、项目 Context、带权重完成度或项目核心。

## 风险

- 结构化纪要可能遗漏细节、抹平分歧或错误表达人的判断；事实、判断、agent 建议和失败尝试必须分开，每个纪要需要来源、版本、新鲜度和纠正路径。
- 个人对话可能包含密码、个人数据、未发布代码或无关内容；必须提供预览、敏感级别、接收人、脱敏、保留、导出和删除控制。
- 团战板到 agent 的内容可能带有提示词注入或恶意产物链接；连接器必须把它视为不可信输入并保留本地权限检查。
- 人类、agent、连接器和系统身份可能混淆；审计事件必须区分它们，并禁止把 agent 操作显示成人类操作。
- 不同 agent 产品支持的继续执行、推送、附件和审批能力不同；通用协议可能需要能力协商与轮询降级。
- 重连与重试可能重复创建任务、验收或伤害；需要稳定 id、幂等、确认和回放规则。
- 中央上下文可能过时或过大；上下文包需要受众、有效期、替代关系和按任务检索。
- 原始产物副本可能包含恶意文件、密钥、个人信息、未授权代码或受版权限制内容；上传需要权限、类型与大小限制、扫描、校验、保留、删除和访问审计。
- 按任务组装 Context 可能跨项目泄露内容或形成摘要循环失真；检索必须执行项目与受众权限，保留来源链，并阻止没有新来源的摘要被反复当作新事实。
- 游戏反馈可能淡化严肃工作或变成绩效监控；个人伤害排行不在范围内，证据始终优先。
- Query 武器奖励可能鼓励刷消息或暴露工作模式；Query 脉冲不含内容或绩效分数，使用短保留期并支持用户关闭。界面可以合并视觉提示，但不能合并不同事件 id 已经获得的武器权益。
- 带权重条件可能配置不当或被操纵；项目负责人需要透明总权重、验收责任、重新打开行为和变更历史。
- 公开部署会引入认证、租户隔离、加密、运维、滥用治理和合规义务，超过当前本地 Harness 的信任模型。
